Dois Cisco 2911 (R1-BASE e ISP), um 2960-24TT (SW1), um AccessPoint-PT, dois Server-PT, dois PC-PT e um Laptop-PT com WPC300N. R1 usa router-on-a-stick; o trunk 802.1Q transporta VLANs 10, 20 e 30.

3. Configurações de referência

Trechos dos arquivos de network/configs para conferência com show running-config. São a configuração prevista, copiada das fontes, e não uma saída coletada de um .pkt executado. Após aplicar os comandos, conferir no modo privilegiado e salvar com write memory.

3.1 SW1 · VLANs e trunk

Uma VLAN por setor; Gi0/1 transporta as três até o R1. O 2960 já usa 802.1Q.

vlan 10
 name EQUIPE
exit
vlan 20
 name CIDADAO_WIFI
exit
vlan 30
 name SERVIDORES_SENSORES
exit
!
! O 2960 usa 802.1Q; nao inserir switchport trunk encapsulation dot1q.
interface GigabitEthernet0/1
 description TRUNK_PARA_R1_G0/0
 switchport mode trunk
 switchport trunk allowed vlan 10,20,30
 no shutdown
exit
!

Fonte: network/configs/SW1.txt.

Fa0/1 é Equipe; Fa0/2 é Wi-Fi; Fa0/3–4 são servidor e sensor. O endereço de gerenciamento fica na VLAN 10; SW1 não roteia.

exit
interface FastEthernet0/3

exit
interface FastEthernet0/4

3.3 R1 · subinterfaces e WAN

Cada subinterface é gateway de uma VLAN e lado interno do NAT. A interface física do trunk fica sem IP. Gi0/1 é o lado externo.

interface GigabitEthernet0/0
 description TRUNK_8021Q_PARA_SW1_G0/1
 no ip address
 no shutdown
exit
interface GigabitEthernet0/0.10
 description VLAN10_EQUIPE
 encapsulation dot1Q 10
 ip address 192.168.10.1 255.255.255.0
 ip nat inside
exit
interface GigabitEthernet0/0.20
 description VLAN20_CIDADAO_WIFI
 encapsulation dot1Q 20
 ip address 192.168.20.1 255.255.255.0
 ip nat inside
 ip access-group WIFI_CIDADAO_IN in
exit
interface GigabitEthernet0/0.30
 description VLAN30_SERVIDORES_SENSORES
 encapsulation dot1Q 30
 ip address 192.168.30.1 255.255.255.0
 ip nat inside
exit
!
! Saida para o provedor; IP publico compartilhado pelo PAT.
interface GigabitEthernet0/1
 description WAN_PARA_ISP_G0/0
 ip address 200.10.0.2 255.255.255.252
 ip nat outside
 no shutdown
exit

Fonte: network/configs/R1-BASE.txt.

3.4 R1 · DHCP

O R1 distribui IP, máscara, gateway e DNS nas três redes; reservas evitam conflito com gateways, switch e servidor. Não é necessário ip helper-address.

service dhcp
ip dhcp excluded-address 192.168.10.1 192.168.10.9
ip dhcp excluded-address 192.168.20.1 192.168.20.9
ip dhcp excluded-address 192.168.30.1 192.168.30.9
ip dhcp excluded-address 192.168.30.10
ip dhcp pool EQUIPE
 network 192.168.10.0 255.255.255.0
 default-router 192.168.10.1
 dns-server 192.168.30.10
 domain-name ruaviva.gs
exit
ip dhcp pool CIDADAO
 network 192.168.20.0 255.255.255.0
 default-router 192.168.20.1
 dns-server 192.168.30.10
 domain-name ruaviva.gs
exit
ip dhcp pool SERVIDORES_SENSORES
 network 192.168.30.0 255.255.255.0
 default-router 192.168.30.1
 dns-server 192.168.30.10
 domain-name ruaviva.gs
exit
!

Fonte: network/configs/R1-BASE.txt.

3.5 R1 · ACL do cidadão

Ordem: DHCP broadcast e renovação; DNS UDP 53 e HTTP TCP 80 para .30.10; negar VLANs 10 e 30; permitir demais destinos da VLAN 20. Aplicada na entrada de Gi0/0.20. O ping ao servidor é bloqueado, embora HTTP seja permitido.

ip access-list extended WIFI_CIDADAO_IN
 permit udp any eq 68 host 255.255.255.255 eq 67
 permit udp 192.168.20.0 0.0.0.255 eq 68 host 192.168.20.1 eq 67
 permit udp 192.168.20.0 0.0.0.255 host 192.168.30.10 eq 53
 permit tcp 192.168.20.0 0.0.0.255 host 192.168.30.10 eq 80
 deny ip any 192.168.10.0 0.0.0.255
 deny ip any 192.168.30.0 0.0.0.255
 permit ip 192.168.20.0 0.0.0.255 any
exit
!

Fonte: network/configs/R1-BASE.txt.

3.6 R1 · PAT e rota padrão

A ACL 1 seleciona origens para tradução, não é o filtro Wi-Fi. Overload compartilha 200.10.0.2 por portas; a rota padrão aponta ao ISP.

access-list 1 permit 192.168.10.0 0.0.0.255
access-list 1 permit 192.168.20.0 0.0.0.255
access-list 1 permit 192.168.30.0 0.0.0.255
ip nat inside source list 1 interface GigabitEthernet0/1 overload
ip route 0.0.0.0 0.0.0.0 200.10.0.1
!

Fonte: network/configs/R1-BASE.txt.

3.7 ISP · retorno conectado

As redes WAN e externa são diretamente conectadas. O retorno ao PAT alcança 200.10.0.2 sem rotas privadas no ISP; não adicionar rotas às VLANs.

interface GigabitEthernet0/0
 description WAN_PARA_R1_G0/1
 ip address 200.10.0.1 255.255.255.252
 no shutdown
exit
!
! Rede do servidor externo que representa a internet.
interface GigabitEthernet0/1
 description SERVIDOR_INTERNET_FASTETHERNET0
 ip address 8.8.8.1 255.255.255.0
 no shutdown
exit

Fonte: network/configs/ISP.txt.

3.8 R1 · restrição do SSH

Acesso remoto somente SSH e apenas da VLAN Equipe. As fontes também configuram usuário local, SSH v2 e credenciais de exemplo; substituir as senhas antes da entrega e não expô-las nas capturas.

ip access-list standard VTY_EQUIPE
 permit 192.168.10.0 0.0.0.255
 deny any
exit
line vty 0 4
 login local
 transport input ssh
 access-class VTY_EQUIPE in
 exec-timeout 5 0
exit
!

Fonte: network/configs/R1-BASE.txt.

Serviços e Wi-Fi

No SRV-RUAVIVA, ligar DNS e HTTP; DHCP permanece desligado. Registros A: ruaviva.gs → 192.168.30.10 e internet.gs → 8.8.8.8. Publicar network/servidor/index.html como index.html. No servidor externo, publicar network/servidor/internet.html como index.html, com HTTP ligado.

No AP: SSID RuaViva-Cidadao, canal 6, WPA2-PSK e AES. Associar o laptop com WPC300N e solicitar DHCP. Portas não utilizadas ficam desligadas. Conferir também SSH da Equipe e recusa de Telnet.

4. Testes e evidências

Pré-condições: interfaces up/up, VLANs/portas corretas, trunk encaminhando 10,20,30, DNS/HTTP ligados e rotas conectadas no ISP. Conferir show vlan brief, show interfaces trunk, show ip interface brief e show ip route.

As cinco verificações abaixo são critérios de aceitação. As imagens e os resultados observados estão pendentes de execução no Packet Tracer; nenhum resultado esperado é apresentado como teste aprovado.

1. Ping entre VLANs

Origem e destino: PC-EQUIPE → gateway local e SRV-RUAVIVA; PC-SENSOR → gateway da VLAN 10.

PC-EQUIPE:
ping 192.168.10.1
ping 192.168.30.10
PC-SENSOR:
ping 192.168.10.1

Resultado esperado: Respostas estáveis entre VLANs 10 e 30. Repetir após resolução ARP inicial. Não usar laptop como destino da Equipe: a ACL bloqueia o retorno ICMP.

Resultado observado: pendente. Registrar data, versão do PT e identificação da execução junto à captura.

2. DHCP nos três setores

Origem e destino: PC-EQUIPE, LAPTOP-CIDADAO associado e PC-SENSOR, com ACL já aplicada.

Em cada cliente:
ipconfig /release
ipconfig /renew
ipconfig /all
No R1:
show ip dhcp binding
show ip dhcp pool

Resultado esperado: Equipe .10.10–254; cidadão .20.10–254; sensor .30.11–254. Máscara /24, gateway .1 da própria VLAN e DNS 192.168.30.10. Capturar concessões e renovação com a ACL ativa.

Resultado observado: pendente. Registrar data, versão do PT e identificação da execução junto à captura.

3. Página acessada pelo nome

Origem e destino: Navegador do PC-EQUIPE e do LAPTOP-CIDADAO.

http://ruaviva.gs

Resultado esperado: Ficha da CitizenTech com localização, nomes e RMs; URL visível. Demonstra resolução DNS e HTTP. No cidadão, confirma as permissões UDP 53/TCP 80 anteriores ao bloqueio da VLAN 30.

Resultado observado: pendente. Registrar data, versão do PT e identificação da execução junto à captura.

4. NAT/PAT e internet simulada

Origem e destino: PC-EQUIPE e LAPTOP-CIDADAO → servidor externo 8.8.8.8.

Navegadores:
http://internet.gs
No R1, imediatamente após o acesso:
show ip nat translations
show ip nat statistics

Resultado esperado: Página “Internet simulada”. Tradução TCP: Inside local = IP/porta reais do cliente; Inside global = 200.10.0.2:porta; destino = 8.8.8.8:80. Registrar a tabela antes de expirar; DNS interno não precisa gerar NAT.

Resultado observado: pendente. Registrar data, versão do PT e identificação da execução junto à captura.

5. Bloqueio por ACL

Origem e destino: LAPTOP-CIDADAO → IP concedido ao PC-EQUIPE e SRV-RUAVIVA.

No PC-EQUIPE: ipconfig
No laptop (substituir pelo IP observado):
ping 192.168.10.10
ping 192.168.30.10
No R1, antes e depois:
show access-lists
show access-lists WIFI_CIDADAO_IN

Resultado esperado: Sem respostas de eco aos dois destinos; os contadores deny das redes 10 e 30 aumentam. HTTP da solução continua funcionando. Se o PT não exibir contadores, capturar também a PDU ICMP descartada em Simulation.

Resultado observado: pendente. Registrar data, versão do PT e identificação da execução junto à captura.

Salvar como network/RuaViva.pkt, reabrir e repetir os testes para verificar persistência. A ACL não isola cidadãos dentro do mesmo segmento Wi-Fi. A página HTTP do laboratório apresenta a ficha; não executa a API.
